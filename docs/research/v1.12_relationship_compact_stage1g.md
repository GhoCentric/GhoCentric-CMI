## What was tested

Phase 1G introduces a research-only, task-blind lossless representation for the
current relationship manager's per-pair state. Production relationship transition
logic remains authoritative and unchanged.

The first prospective run discovered that relationship-pair insertion order is
publicly observable because `RelationshipManager.tick()` emits relationships in
the current mapping iteration order. The candidate therefore preserves that order
as part of the lossless state contract rather than sorting pair identifiers.

The next prospective run exposed a separate runtime integration invariant: the
relationship manager's `_rels` dictionary is a backing container participating in
the owning snapshot/state graph. Rebinding `_rels` preserved live relationship
reads but detached the manager from the snapshot owner. Phase 1G therefore restores
decoded relationship state by mutating the existing dictionary in place and
requires backing-container identity plus full-snapshot parity.

Prospective validation used all 15 current public relationship event types and all
9 preregistered intensity values. Candidate state was reconstructed into restored
Ghost instances before unseen continuation workloads. Return packets, relationship
packets, downstream host-decision projections, compact restart checkpoints, and
final full snapshots were required to match exactly.

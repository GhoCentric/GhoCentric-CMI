DETERMINISTIC STATE ENGINE

A system for software that needs to remember what happened.

GhoCentric CMI keeps an agent's changing state in one inspectable model. Feed it ordered events, read the resulting state, snapshot it, restore it, and continue from the same history.

INSTALL pip install ghocentric-ghost-engine

Python package: ghost · Core dependencies: 0 · Snapshot schema: 1.0 · License: Apache-2.0

01

THE MODEL

State is structured instead of flattened into one score or one prompt.

CMI separates different kinds of state so they can change independently. A relationship can remain friendly while anger rises. A belief can change without rewriting the fact it refers to. Attention can move without deleting what was previously stored.

relationship
Accumulated interpersonal state affected by ordered interactions.
emotion
Emotional pressure and temperament-sensitive state kept separate from relationship history.
belief + evidence
Facts, observations, reports, evidence, and actor beliefs remain distinguishable and revisable.
interpretation
The meaning an event has to a particular agent without overwriting the source event.
attention
What is foregrounded now without treating everything outside focus as forgotten.
continuity
Ordered state that can be serialized, restored, and continued deterministically.

WHERE CMI SITS

Events go in. Structured state changes. Your application decides what to do with it.

STATE structured state · snapshot · restore
HOST game · app · agent · optional LLM

WHAT USING CMI LOOKS LIKE

The smallest useful loop is straightforward: apply an event, read the resulting state, snapshot it, and restore it later.

from ghost import GhostAPI

ghost = GhostAPI()

ghost.apply_event(
    "player",
    "shopkeeper",
    {"type": "help", "intensity": 1.0},
)

relationship = ghost.get_relationship(
    "player",
    "shopkeeper",
)

snapshot = ghost.snapshot()
ghost = GhostAPI.from_snapshot(snapshot)

This exact lifecycle is executed against the current v1.12.0 source by the site-build gate before the example is accepted.

03

PRODUCT BOUNDARY

CMI owns state. Your application owns behavior.

CMI

structured state · deterministic transitions · continuity · JSON-safe snapshot / restore

YOUR HOST

dialogue · rendering · animation · game rules · final actions · UI · orchestration · whether an LLM is used at all

CMI does not generate a character's final line or decide what a game should render. It gives the host a persistent, inspectable state model to use when making those decisions.
